# 服务器 L4：第一阶段，真实权重的 attention 子图数值验证

后续完整单层、真实 QuaRot→FlexSmooth 生命周期串联使用
[第二阶段交接说明](layer_l4.md)。需要新 cache；本页的第一阶段结果与范围保持不变。

这套工具与 `glm52_precision_probe.py` 配合使用。旧 probe 只读文件头；新工具读取
**指定一层的 attention 投影和三个 norm 权重值**，在 CPU 上执行实际 LLMC 变换函数，
与外部 ModelSlim 原始函数比较。不会构造、下载、量化或运行完整 GLM-5.2。
每次只选一层；full/shared indexer 各选一层时分别运行。

本阶段是有明确范围的 L4，不代表整个 decoder layer、BF16/NPU kernel 或整模型
精度通过。MLP/experts/router/lm_head、attention softmax/RoPE/top-k、真实模型上的
Modifier 生命周期和 QuaRot→FlexSmooth 串联尚需后续验证；MXFP 规则差异另行处理。
报告中的 `full_layer_l4_passed` 始终为 false，本阶段通过也不能据此启动 L5。

## 已收到的服务器结果（2026-09-23）

真实 BF16 权重和一个 18-token baseline prefill 的缓存，在 FP32 CPU 上对比：

| 所选层 | 子图检查 | 最大浮点相对 L2 | 状态 |
|---|---:|---:|---|
| 0，full indexer | 79 | 2.8403e-6 | scoped L4 PASS |
| 3，shared indexer | 58 | 3.1673e-6 | scoped L4 PASS |

报告中的 reference 矩阵、fusion/rotation 权重、FlexSmooth scale/权重/候选 loss
比较误差为 0；上表最大误差来自 O 投影变换前后的坐标等价性检查。
两个原始 cache 的 SHA256、metadata、FP32 输入哈希、统计和各处权重指纹交叉核对通过。
本机没有真实层权重，因此没有在本机重跑这些真实权重变换；数值误差来自服务器报告。

服务器通过的版本包含 `rotate_axis` 的 2D GEMM 修复，避免 group/batch 维度让旋转
矩阵进入可能产生巨大临时分配的广播路径。服务器 `rotation.py` 的 SHA256 为
`5e1864bed6fdbf027c255939dde2cb407cf6e4594c617f4d568241c77eeef7dd`，原样应用修复时
与本地一致。随后 Ruff 将一处多行调用合并为单行，当前 LF SHA256 为
`94553cf867b6f20e2773cc5166c77e17da8ecf0ed8b0654d362eba649232cee3`；两版 AST 完全相同。
小张量 dispatch 回归检查不触发 batched GEMM；无需复现服务器上的大规模 OOM。
服务器使用 torch 2.10.0，当前本机完整 L0–L3/交接回归为 168 passed、0 skipped。

这是一条短输入、两种 attention 布局的证据，不增加上文未覆盖范围，也不解决 MXFP
的跨框架规则差异。真实 cache 是独立算法的 baseline，不能当作 QuaRot 后的校准输入。

## 环境与假设

需要当前开发分支的完整仓库（包含 tools、tests 中的外部 oracle adapter）、可导入的
当前 LLMC、PyTorch、safetensors、Transformers、compressed-tensors、NumPy 和 packaging。
ModelSlim 只需服务器已有源码目录；工具按 AST 执行选定原始定义，不必安装整套 NPU
后端，也不复制其算法源码。仅复制新脚本单文件不足以运行；旧 probe 仍可单文件运行。

本机脚本测试使用 Python 3.12、torch 2.14.0+cpu、Transformers 5.17.0、CT
0.19.1a20260919。工具语法要求 Python 3.10+，实际可用版本还受 LLMC 依赖约束。
参考源码基线是 ModelSlim `beb917d011bc1d11a8bf5e46f62928f6d84b06a7`；不同版本的
定义变化可能导致明确报错，返回报告后分析，不应手动删掉失败检查。

待验证假设：

1. 选层是普通 decoder，checkpoint 中 MLA/indexer 的名称、维度与当前子图契约一致。
2. 在真实权重的 FP32 副本上，QuaRot 的 norm fusion、四个旋转空间及配对投影保持
   等价，与 ModelSlim 原始函数一致。
3. 在相同 baseline activation 样本上，FlexSmooth 的 alpha、beta、42 个候选 loss、
   scale 和变换权重与 ModelSlim 一致；norm-linear 和 OV 的浮点关系保持等价。

QuaRot 和 FlexSmooth 分别从同一原始 baseline 开始；这里不混用 QuaRot 后 cache，
也不把两套独立实验宣称为串联验证。最终量化不在本工具中执行。

## 1. 先确认读取范围，再运行无 cache 预检查

在当前开发分支仓库根目录运行，路径替换为服务器已有目录。输出文件必须是新文件，
且位于 checkpoint / ModelSlim 目录之外。脚本拒绝覆盖已有报告或 cache。

```bash
python tools/glm52_l4.py \
  --model-dir /models/GLM-5.2-BF16 \
  --layer 0 --dry-run \
  --output /tmp/glm52-l4-plan-0.json
```

这一步仍只读 header，报告列出将读取的精确 tensor、维度、FP32 权重字节数和
工作内存估算。默认 selected weights 上限 2 GiB，工作内存估算上限 16 GiB；超出时
在 payload 读取前停止。后者是保守规划估算，不是操作系统硬内存限额。
服务器确认余量后才调整 `--max-weight-gib` / `--max-estimated-memory-gib`。
运行时维护几份选定权重、矩阵和搜索临时张量，实际耗时取决于层维度和 CPU。

```bash
python tools/glm52_l4.py \
  --model-dir /models/GLM-5.2-BF16 \
  --modelslim-source /code/msmodelslim \
  --layer 0 --synthetic-activations --tokens 16 --threads 4 \
  --output /tmp/glm52-l4-precheck-0.json
```

这一条已经读取真实选层权重，但输入是固定 seed 的随机数。
成功时退出码 **3**、`status=precheck_only`，`scoped_l4_passed=false`。
它可提前发现真实维度/权重的数值问题，不能冒充真实 activation 验证。

## 2. 在已有 BF16 推理代码中采集少量真实 activation

采集工具不加载模型、不调用 forward。把下面 context 放在**已有、可运行的 PyTorch
baseline 推理流程**中，包住一次短文本 prefill。`model` / `inputs` 沿用原流程；
不要为此另启完整量化任务。此 helper 不能直接挂到 vLLM Engine 的融合算子上。

```python
import torch
from tools.glm52_l4_capture import capture_inputs

# model 已由服务器原有流程加载；inputs 是原有 tokenizer 的真实短文本输入。
# model 应处于 eval 模式，保留原流程需要的 device、attention mask、position 等设置。
with capture_inputs(
    model,
    model_dir="/models/GLM-5.2-BF16",
    layer=0,
    output="/tmp/glm52-layer0-baseline.safetensors",
    input_kind="real",
    input_description="真实短文本 prefill；记录文本来源、tokenizer、mask/position 设置",
    max_tokens=128,
):
    with torch.inference_mode():
        model(**inputs)  # 换成原流程已有的前向调用，保持原有调用参数。
```

采集 input_layernorm、q_a_layernorm、kv_a_layernorm 的输入/输出，以及 kv_b_proj、
o_proj 的输入。每个位置只保留前 128 个 token，flatten 后形状为 `[tokens, channels]`。
metadata 记录 baseline 阶段、层号、config SHA256、选定权重 SHA256、样本说明与数量。
权重哈希会临时将**选定参数逐个**复制到 CPU，且结束时再次检查权重没有变化。
输入必须与已有 checkpoint 一致；合成数据必须声明 `input_kind="synthetic"`。

工具不改变 forward 的输入/输出，异常也会清理 hooks。若融合实现绕过这些 module、
没有触发必要 hook，会报缺失位置且不写 cache；把错误返回，按实际运行结构适配。
不要把空 cache 当作完成。这里不重放完整 attention，因此没有保存 mask/position
tensor；其运行设置写入描述，完整 attention L4 后续另做。

如果已有 activation cache，先返回键名、shape/dtype 和采集阶段说明，由我们适配
该格式。不要直接改 metadata 把变换后数据标成 baseline。

```bash
python tools/glm52_l4.py \

  --modelslim-source /code/msmodelslim \
  --layer 0 --activation-cache /tmp/glm52-layer0-baseline.safetensors \

```

工具校验 cache 的阶段、层号、config 和全部选定权重哈希。不会把旧模型、另一个层

可以校验数值/哈希，不能独立证明文本来自真实数据集。

## 判据、返回材料与边界

- rotation matrix 与 reference 精确相同；对每个矩阵的前 `min(size, 2*block_size)`
  行额外抽查正交性，最大绝对误差 ≤1e-5。这是抽查，不声称计算了全尺寸 QᵀQ。
- fusion / 每步旋转权重 / smoothing scale / 候选 loss：相对 L2 ≤1e-5。
- alpha/beta 精确相同；候选 loss 出现非有限值会判为需要分析，不静默略过。
- Q、K、V、RoPE 投影、O 投影及 norm-linear 输出关系：相对 L2 ≤1e-4。
  V/O 输出按相应旋转坐标比较；不把不同坐标下的值直接比较。
- FlexSmooth OV 的 K 权重行逐元素完全不变；所有比较检查有限值。
- ModelSlim 使用原始函数；QuaRot 的分段调用逐 head 执行原始 rotate_linear，避免
  构造整层巨大 block diagonal 矩阵。不是完整 ModelSlim processor 或 scheduler。

退出码：0 = dry-run 成功或真实 cache 的所选子图通过（务必查看 status）；
1 = 数值不通过；2 = 输入/配置/运行错误；3 = 合成输入预检查通过。
仅真实来源 cache 且所有数值检查通过才有 `scoped_l4_passed=true`。

请先返回 **JSON 报告 + 控制台日志**。报告含版本/源码哈希、所读 tensor、输入/权重
统计、各项误差、alpha/beta、两阶段全部 loss 和 scale 统计；不含完整权重。
activation cache 留在服务器，需要定位问题时再选取小块 tensor 返回。
任何失败先分析本次报告，不进行完整 GLM-5.2 量化或 L5 精度评估。
